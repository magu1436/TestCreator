# Cloud Run へのデプロイ

汎用コンテナの構築・DB設定は [本番環境の構築と実行](../../docs/deployment.md) を参照してください。
Cloud Run 固有の設定例・スクリプト・ドキュメントはこのディレクトリで管理します。
ルートの Dockerfile と entrypoint.sh は共通のものを利用します。

## コンテナの設定

- `DJANGO_SETTINGS_MODULE=TestCreator.production` はイメージの既定値です。
- PDF 出力先には `OUTPUT_PDF_DIR=/tmp/exports` を設定してください。以前の `K_SERVICE`／`GAE_ENV` による自動選択は行いません。
- `PORT` は Cloud Run が渡します。アプリはそのポートを `0.0.0.0` で待ち受けます。
- 公開ホストに対応する `ALLOWED_HOSTS` と、必要な `CSRF_TRUSTED_ORIGINS` を指定します。
- DB設定は `DB_*` を使用します。旧 `TIDB_*` は使用しません。
- 秘密鍵・DBパスワード・OCRキーは実行環境の秘密情報として渡し、リポジトリやイメージには含めません。
- TiDB用CAはコンテナから読める場所へ配置し、そのパスを `DB_SSL_CA` に指定します。

Cloud Run のファイルシステムは一時的なメモリ上の領域です。PDFやアップロードデータの永続保存先にはできません。
アップロードを保持する運用では、別途永続ストレージを設計してください。

設定値の例は [環境変数の例](environment.example.yaml) を参照してください。このファイルは説明用で、秘密情報や実際の接続先を記入してコミットしないでください。

## リリースと既存環境の移行

共通の PR・検証・公開確認は [リリース手順](../../docs/releasing.md) を参照してください。
環境変数移行、トラフィック切り替え、切り戻し、旧ブランチ廃止は [公開・切り戻し手順](release-runbook.md) を参照してください。

1. 作業ブランチから develop 向け PR で実装・検証を行います。
2. リリース対象を確認し、develop → main の PR で統合します。main は現行リリース、develop は未リリース機能を含むブランチとして運用します。
3. 検証済みのリリースコミットから作成したイメージを公開します。main へのマージと本番公開は別操作です。
4. 公開成功を確認し、対応するリリースタグを付けます。

既存環境を切り替える前に、Cloud Run／ビルド設定側で次の項目を確認してください。このリポジトリだけでは現在の実環境設定は確定できません。

- イメージを作成する仕組み、参照リポジトリ・ブランチ、イメージの保存先と識別方法。
- 旧 deploy ブランチを参照するトリガーの有無と、main への切り替え方法。
- 環境変数、秘密情報、CA、DBへのネットワーク接続、サービスアカウントの設定。
- 検証先での起動・静的ファイル配信・ログイン・PDF生成と、公開後の確認・切り戻し手順。

deploy ブランチは移管と参照先の確認が終わるまで残し、今後の変更の統合先にはしません。
実際のプロジェクト・サービス・ビルド経路が確定するまでは、既存サービスを更新するコマンドを実行しないでください。
